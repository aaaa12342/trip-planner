# 先选景点，再生成路线

更新日期：2026-10-15。

1. 填写目的地，在输入框下方查看景点卡片。已收录目的地立即显示；其他地点点击“查看推荐景点”，遇到重名地点先选择候选。
2. 查看景点简介、看点、类别与建议时长，勾选想去的景点。默认勾选推荐列表，可全选或清空。至少选一项才能生成。
3. 设置出发地、日期、天数、方式与节奏，点击“按所选景点生成路线”。快捷路线只填写目的地并跳到景点选择，不直接生成。
4. 在概览下阅读每日逐站路线：每个景点有建议时长和游玩内容，两站之间有交通建议、估算分钟数、直线距离及地图链接。时间预算放不下的已选景点列为备选，可增加天数或手动调整。
5. 火车、高铁、飞机行程先比较推荐抵达站点。根据首个游览景点距离 70% 和所有已安排景点平均距离 30% 排序；高铁优先采用资料标明的高铁站，其他铁路站标为车次待核实备选。可手动切换，交通、住宿与地图同步更新；保存或导出 JSON 会保留选择。实际班次、运营和从出发地是否可达需购票前核实。
6. 在路线下查看自动加载的地图。默认聚焦目的地，可切换每日景点或含出发地的完整旅程；地图标记序号对应逐站路线与景点详情。
7. 后续可以调整日期与景点顺序，交通衔接随顺序更新。恢复存档时同时恢复景点选择；链接分享仅分享输入与偏好，完整手动攻略通过 JSON 导出。

## 交通与地图边界

短距离优先给出步行建议，其他衔接依据公共交通、打车、自驾、包车或租车设置。存在地铁资料时展示对应站点提示；资料不足时提示查询，不提供未经核验的班次和换乘方向。交通分钟数是规则估算，地点坐标也是规划参考点，实际路线、入口、拥堵、排队和预约需出发前确认。

每段交通使用 [高德路径规划 URI](https://lbs.amap.com/api/uri-api/guide/travel/route)，分别携带起终点与步行、公交或驾车方式；坐标按 [URI 文档](https://developer.amap.com/api/uri-api/gettingstarted) 指定为 WGS84。点击链接才打开外部地图。

Leaflet 组件随项目保存在 `vendor/leaflet`，包含 BSD 许可证；采用官方支持的 [本地提供方式](https://leafletjs.com/download.html)。在线底图使用 OpenStreetMap，已移除要求密钥的 CARTO。file:// 页面按 [OSM 官方指引](https://wiki.openstreetmap.org/wiki/Referer) 发送 X-Requested-With 应用标识。导航顺序与正文一致：概览、行程、地图、天气、住宿、景点。底图服务无法访问时，本地路线和编号标记仍然保留，并显示失败提示。每日景点连线是顺序示意，不代表真实道路或公共交通轨迹。

## 本次验证

36 项规则测试、36 个浏览器场景通过。包括生成前勾选、清空后阻止生成、交通模式切换、未知目的地确认、查询取消、file:// 本地打开、CDN 阻断、底图失败、保存恢复与四种屏幕宽度。

常规浏览器回归替代第三方接口和瓦片。另于 2026-10-15 使用直接打开的 file:// 页面进行一次真实底图检查：15 张当前视口瓦片正常加载、2 个景点标记正常，截图已核对道路及标签；天气查询在该检查中仍为模拟失败。该结果仅代表当次本机访问，不保证服务持续可用。底图状态区分加载中、全部成功、部分失败与路线示意；对实际遇到的 HTTP-200 访问受限提示图增加识别。

抵达站点至首个景点以紫色标记与连线呈现，仍为直线示意。若首日直接游览，该段估算替换原市中心至首站估算并计入预算；如果首个游览日在后续日期，只提供衔接参考，不假设在站点过夜或重复计入后续日预算。
