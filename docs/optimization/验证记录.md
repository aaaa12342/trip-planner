# 逐项优化与验证记录

完成日期：2026-10-06。对应 [优化目录](../../优化目录.md)。

## 01 稳定性与安全 — 已完成

修复住宿模块作用域错误；统一 JSON 请求的超时、取消、有限内存缓存与格式检查。取消生成会同时停止地图请求及清理旧地图。主流程失败时取消其他请求。结果渲染转义外部文字，导入内容通过字段白名单重建。

验证：超时、取消、缓存、不合法响应不入缓存；生成中重置、防抖中重置、快速切换、天气异常、天气格式异常、地图失败、定位失败和恶意文本浏览器检查通过。

## 02 知识库与数据校验 — 已完成

新增 `js/catalog.js` 和自动结构检查，基础城市的景点字段统一为空数组。景点别名支持明确指向城市，修复“张家界国家森林公园”别名未解析的问题。时长解析支持分钟、半小时、小时范围、半天和天数范围；多日景区不截断成一天。

验证：220 个城市、71 个景点目的地、40 份住宿资料、183 个城市内景点结构检查无错误或警告；1,746 种目的地与天数组合检查通过。此项验证坐标范围与结构，不代表实地信息、开放时间或文字事实的在线核验。

## 03 目的地输入与定位 — 已完成

起终点输入接入 291 个本地目的地的浏览器补全。联网地理编码存在多个候选时打开原生对话框，显示行政区、国家和坐标供用户选择。起终点同时需要选择时串行显示，取消或重置可关闭窗口并终止排队任务。

验证：候选选择、取消、重置后不恢复窗口和旧结果通过；规则测试证明未按人口静默选择同名地点。

## 04 行程算法与编辑 — 已完成

轻松、舒适、紧凑分别使用不同每日时间预算；公共交通与汽车类使用不同交通耗时估计。推荐天数结合勾选景点的游览时长。编辑面板支持勾选、移到任意一天/备选、上移和下移；重新规划使用当前勾选。手动超出预算或把全天景点与其他景点放在一起会提示，保留用户安排。编辑同步更新行程、住宿、公交衔接和已加载地图。

验证：节奏/方式改变估算、手动超时、移动顺序、排除景点、多日景点不被缩短和浏览器编辑流程通过。自动规划为启发式，不声称全局最优，也未纳入实时票务或开放时段。

## 05 住宿推荐偏好 — 已完成

新增 `js/stay-engine.js`。支持景点便利、交通优先、安静休闲偏好，按已安排景点和所选出行枢纽距离排序。机场采用最近机场；安静偏好依据资料描述，资料缺失时给出提示。首选区域展示推荐依据。

验证：便利/安静/飞机交通优先的排序差异及解释通过规则测试，浏览器可切换偏好。评分使用直线距离和描述信号，不等于真实房价、酒店质量或噪声保证。

## 06 保存、恢复与分享 — 已完成

本机 localStorage 保存最近 10 份攻略。恢复保留已勾选景点和手动顺序，天气标为存档时数据。JSON 支持导入导出，限制版本、大小、坐标、字段类型、日期、枚举及景点索引；失败导入不替换当前攻略。分享链接仅携带输入与偏好，接收者主动生成；手动攻略通过 JSON 分享。

验证：浏览器保存、恢复、下载、导入和删除通过；规则测试覆盖重复/越界索引、非法版本、超大文件、额度不足不覆盖原存档及最近十份限制。分享链接重新打开后恢复输入，不自动请求天气。导入读取期间发生重置或输入变更时不会恢复旧文件。

## 07 页面与地图体验 — 已完成

新增模块导航、地点选择对话框、来源时间、存档提示、偏好控件和编辑反馈。地图脚本、样式及道路路线改为点击后加载，支持备用 CDN；按天查看聚焦目的地并保留全局景点编号。地图失败不影响主攻略，打印视图隐藏编辑控件和交互地图。

验证：键盘展开、候选对话框、按需加载、每日地图范围、320/375/768/1280 像素宽度及打印检查通过。截图已检查；地图瓦片、天气及路线接口在测试中使用替代数据，运行的是实际 Leaflet 1.9.4 组件。

## 12 导航顺序与真实底图 — 已完成

2026-10-15：修复导航遗漏，顺序与正文统一为“概览 → 行程 → 地图 → 天气 → 住宿 → 景点”。静态检查会校验锚点存在且按正文顺序排列。

截图中的 CARTO 提示图可以正常触发图片加载事件，旧实现因而误报成功。依据 [CARTO 官方说明](https://carto.com/basemaps/apikey/) 移除该来源。真实测试进一步发现，无 HTTP Referer 的 file:// 请求也可能得到 HTTP 200 的 OSM 访问受限图片。按 [OSM 官方本地文件指引](https://wiki.openstreetmap.org/wiki/Referer) 使用自定义瓦片加载器发送应用名称，不伪造浏览器来源或用户身份；HTTP 页面保留正常 Referer 与缓存行为。

加载器支持超时、取消与 Blob URL 释放，拒绝失败 HTTP 响应、非图片、解码失败及当次实际观测到的访问受限提示图指纹。后者是针对已知样例的识别，不声称通用识别所有供应商的提示图。底图状态根据当前视口实际完成情况显示：加载中、成功、部分失败或无底图路线示意。失败后可手动重试。

验证：27 项规则测试、33 个浏览器场景及脚本/资源/导航静态检查通过。新增覆盖 HTTP 200 提示图、本地请求应用标识、加载中不得显示成功、网络失败后重试恢复。常规回归仍使用替代接口与瓦片。

另执行一次 `node tests/live-map.cjs` 单视口真实检查：file:// 打开项目，当前视口 15 张真实 OSM 瓦片全部成功、2 个景点标记正常、导航顺序正确，`trip-map-live-fixed.png` 截图已人工查看。该检查仅替代天气为失败，瓦片未被模拟；未做地图预取、批量下载或自动平移扫描。这只验证当次本机访问，不代表第三方服务持续可用。

## 13 抵达站点推荐 — 已完成

2026-10-15：按用户确认方案新增 `js/arrival.js`。火车/高铁使用铁路候选、飞机使用机场；按首个实际游览景点距离 70% 与已安排景点平均距离 30% 排序，不将备选景点混入均值。高铁优先采用现有资料明确标注的候选，其余铁路站保留为“车次待核实”备选；不把普通站分类误当成一定不通高铁，也不推断车次/航线可购。

支持自动推荐与人工切换。首日直接游览时，将抵达站点至首站的估算替换原中心至首站的估算，超预算提示，不删除景点；后续日才游览时仅显示衔接参考。住宿评分以实际选择的站点计算交通距离，地图新增紫色抵达标记和首站衔接示意。站点查询过滤无名和类型不符元素，铁路/机场候选分别保留，资料不足明确降级。自驾等模式不展示不相关的站点推荐。

存档增加可选 `arrivalStationIndex`，严格校验整数、范围及出行类型兼容；旧版文件缺失该字段时自动推荐。手选站点在景点调整、同类型行程重新生成和存档恢复后保留，跨出行类型时清除不兼容选择。

验证：36 项规则/数据测试、36 个浏览器场景通过，19 个应用脚本及资源、ID、导航顺序检查通过。新增规则覆盖距离权重、首站重排、铁路/机场隔离、高铁分类待核实、无候选、备选不参与、交通预算不重复累计、后续日衔接、住宿比较与存档非法引用。新增浏览器场景覆盖机场手选后的交通/住宿/地图联动与保存恢复，高铁待核实提示、出行类型切换、站点查询失败降级；320/375/768/1280 像素和打印检查通过，手机与桌面推荐卡截图已人工查看。

本项使用既有本地资料与模拟接口验证联动，没有验证实际车次、航线、票价或站点当日运营。已确认设计见 [设计说明](../superpowers/specs/2026-10-15-arrival-hub-design.md)。
