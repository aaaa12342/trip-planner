# 旅行工作台设计与技术决策

更新日期：2026-10-15。整合抵达站点、工作台和动效设计，以当前实现为准。

## 先选景点，再生成路线

目的地输入后优先展示本地景点；无本地资料时明确查询并确认候选地点。选定景点才生成日程。自动日程按每日预算与地理距离安排，放不下的景点保留为备选；手动调整允许超预算并明确警告。

## 抵达站点

火车、高铁、飞机行程比较对应站点。评分使用首个实际游览景点距离 70% 与全部已安排景点平均距离 30%，不混入备选。飞机仅机场、铁路仅铁路站；高铁优先采用资料明确标注的候选，其他铁路站标明车次待核实。

用户可手选或返回自动推荐。排序变化保留有效手选，跨目的地和不兼容出行类型时清除。查询失败、候选不足、无已安排景点均明确提示，不虚构站点、车次、航线或可购状态。

首日游览时，以抵达站点到首站的交通替换市中心到首站估算，避免重复累计；超过预算只提示，不删除景点。后续日才游览时仅给衔接参考。住宿以选定站点比较交通距离，地图显示站点与首站的紫色衔接示意。存档的 arrivalStationIndex 为可选字段，旧存档自动推荐，越界、非整数和类型不符均拒绝。

## 工作台布局

主色为雾白 #F4F7F9、白色 #FFFFFF、海蓝 #173E50、青绿 #087E82，次要文字 #546C79。中文系统无衬线字体，正文基准 16px，自有辅助文字不低于 13px，数字使用 tabular-nums。主标题约 28px，模块标题约 20px。

采用左对齐、紧凑品牌和三步导航。桌面主栏选择景点与出行设置，侧栏显示摘要和存档；生成后路线与地图并排，地图在阅读范围内跟随。窄屏依照 DOM 顺序排列。结果导航与正文保持“概览、行程、地图、天气、住宿、景点”的顺序。

高级偏好、存档和推荐依据用原生 details 展示，错误和预算警告保持直接可见。触屏直接呈现完整景点简介。已有推荐列表时隐藏重复查询；查询可取消、失败可重试；批量按钮只在操作有意义时显示。

## 状态与摘要

app.js 负责输入、景点选择和当前攻略，摘要直接由主流程维护。输入、勾选、全选、清空、生成、手动编辑、恢复和重置均同步摘要，ui.js 负责步骤导航等展示辅助。阻断辅助脚本不影响摘要。更新后的 app.js / ui.js 以内容哈希版本引用，降低旧资源缓存造成的不一致。

## 动效

本地 GSAP 3.15.0 核心与独立 motion.js 提供可选动画。一次首屏入场；选择、生成、路线编辑、步骤状态与展开详情触发短反馈，主要使用 transform / opacity，约 200–420ms。列表最多 8 项、编辑最多前两个日程块。保留原生滚动，不对粘性地图的祖先做位移。

GSAP matchMedia 随减少动态效果及屏幕/打印状态清理上下文、观察器和事件处理。打印前完成动画，缺少动画库仍正常显示和操作。许可、上游版本及完整性记录见 vendor/gsap。

## 地图与验证

本地 Leaflet 1.9.4 配合在线 OSM 底图；状态以当前视口有效瓦片为准。底图失败保留路线和标记。每日景点及铁路/航空连线是顺序示意，非真实交通轨迹。

规则和模拟浏览器回归、真实单视口地图检查分别记录。验证 320/375/768/1280 布局、键盘焦点、取消旧请求、存档和打印；taste 另检查 1440/768/390 截图。taste 的宣传页规则不作为应用验收门槛，原始结果见 [审查记录](optimization/taste-review.md)。
