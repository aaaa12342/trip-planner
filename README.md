# 🧭 旅行攻略生成器 · Trip Planner

一个**纯静态、无需后端、无需注册、无需 API Key** 的旅游攻略生成网页。输入**起点**和**目的地**，先查看并勾选推荐景点，再生成包含逐站交通建议的攻略。可部署到 GitHub Pages。

优化清单与完成状态见 [优化目录](优化目录.md)，逐项验收见 [验证记录](docs/optimization/验证记录.md)。

界面采用暖白与深绿配色、SVG 图标及旅行路线插画；桌面规划与存档分栏，手机自动适配。支持快捷路线、键盘跳转和随阅读位置高亮的模块导航。

## ✨ 功能

- **输入**：起点、终点、出发日期（内置目的地补全，联网定位出现同名地点时由用户选择）
- **偏好**：轻松 / 舒适 / 紧凑节奏，景点便利 / 交通优先 / 安静休闲住宿
- **可切换模块**（点击即可切换，切换后自动重新生成）：
  - 🚗 出行方式：自驾 / 打车 / 火车 / 高铁 / 飞机 / 邮轮 / 大巴
  - 🎒 游玩方式：公共交通 / 打车 / 自驾 / 包车 / 租车
  - 📅 游玩时长：一天一夜 / 两天一夜 / 三天两夜 / 四天三夜 / 五天四夜 / 六天五夜
- **景点选择**：选择已收录目的地立即展示景点；未收录地点点击“查看推荐景点”。勾选后生成路线，支持全选与清空。
- **抵达站点**：火车/高铁/飞机按首个景点距离 70% 与已安排景点平均距离 30% 比较站点；显示备选，可手动切换并同步交通、住宿和地图。未确认高铁服务的站点明确标注，车次/航线需另查。
- **输出内容**：
  - 🗺️ 行程概览（含**推荐出行方式 / 游玩方式 / 时长**，并给出推荐理由）
  - 🌤️ 目的地天气（当前 + 按行程天数的逐日预报）
  - 👗 推荐穿搭（按气温、雨雪、目的地类型智能生成）
  - 🎒 推荐携带物品清单（按天气、出行方式、游玩方式、时长分类）
  - 🛣️ 旅游路线（只安排已勾选景点，逐站展示建议游览时长、简介与看点；相邻景点之间展示交通建议、估算时长及地图查询链接；超出预算的景点列为备选）
  - 🏞️ 途经景点介绍（含建议游玩时长）
  - 🍜 美食推荐
  - 📍 旅行路线图（道路出行查询驾车参考路线；飞机/铁路等显示起终点直线示意；各日景点分开连线）
- 🖨️ 打印攻略 / 使用浏览器保存为 PDF
- ✏️ 勾选景点、指定游览日、上移/下移顺序，手动超时提示
- 💾 保存最近 10 份本机攻略，恢复后继续编辑，支持 JSON 导入导出
- 🔗 分享输入与偏好链接（接收者确认日期后重新生成，不包含手动行程）

本地城市景点共 215 个。本次新增石家庄、太原、沈阳、大连、长春、合肥、南昌和福州的 32 个景点，详见 [景点补充记录](docs/attractions.md)。

## 🧱 技术栈

| 能力 | 方案 | 是否需密钥 |
| --- | --- | --- |
| 页面 | 原生 HTML / CSS / JavaScript | 否 |
| 地图 | [Leaflet](https://leafletjs.com/) + [OpenStreetMap](https://www.openstreetmap.org/) | 否 |
| 行进路线 | [OSRM](https://project-osrm.org/)（免费演示服务，失败时自动退化为直线） | 否 |
| 天气 | [Open-Meteo](https://open-meteo.com/)（地理编码 + 预报） | 否 |
| 景点兜底 | [Overpass API](https://overpass-api.de/)（未收录目的地时自动检索当地景点） | 否 |
| 攻略内容 | 内置本地知识库 + 规则引擎（220 个城市条目 + 71 个景点目的地） | 否 |

> 所有数据源均为免费、无需注册，开箱即用。

## 🚀 本地运行

直接双击 `index.html` 即可在浏览器打开（需要联网加载 CDN 与数据源）。

或者用任意静态服务器：

```bash
# Python
python -m http.server 8080
# 然后访问 http://localhost:8080
```

## 🌐 部署到 GitHub Pages

1. 在 GitHub 新建一个仓库（如 `trip-planner`）。
2. 将本项目文件推送上去：

   ```bash
   git init
   git add .
   git commit -m "init: 旅行攻略生成器"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/trip-planner.git
   git push -u origin main
   ```

3. 在仓库页面进入 **Settings → Pages**，将 **Source** 选为 `Deploy from a branch`，分支选 `main`，目录选 `/ (root)`，保存。
4. 几分钟后即可通过 `https://<你的用户名>.github.io/trip-planner/` 访问。

## 🗂️ 扩充目的地

在 [`js/data.js`](js/data.js) 的 `DB` 对象中按现有格式新增城市即可：

```js
'新城市': {
  name: '新城市', province: '省', type: 'city', region: '地区',
  lat: 0, lng: 0,
  overview: '一句话简介',
  attractions: [
    { name: '景点', lat: 0, lng: 0, category: '类型', duration: '2小时', desc: '介绍' }
  ],
  foods: [ { name: '美食', desc: '介绍' } ],
  tips: '小贴士'
}
```

`type` 可选值：`city`（都市）、`historic`（历史文化）、`coastal`（海滨）、`beach`（海岛度假）、`mountain`（山水/自然）、`oldtown`（古城古镇）。

220 个城市中有 48 个收录本地精选景点，共 215 个城市景点；另有 71 个独立景区目的地与 40 份城市住宿资料。其余城市先通过 Overpass 查询附近景点，供用户勾选后规划；查询失败时可重试或更换目的地，不直接生成没有选定景点的路线。

## ⚠️ 说明

- 天气、地图、路线、景点等数据来自第三方免费服务，实时获取，出行前请以官方信息为准。
- 攻略内容由本地知识库与规则生成，仅供参考。
- 距离和住宿评分使用直线距离，市内交通时间为启发式估算；不代表实时导航、真实换乘方案或酒店质量。
- 每日游览预算（单日 / 多日首尾日 / 中间日）：轻松 3 / 4 / 6 小时，舒适 4 / 5 / 8 小时，紧凑 5 / 6 / 9 小时。规则估算公共交通速度 20 km/h、汽车类 30 km/h，并对直线距离乘以 1.3；不是实际路网时间。
- 自动规划优先满足时间预算，全天景点独占可容纳的游览日，不足以安排的景点列为备选。全天景点游览时长不含额外接驳交通，多日景区不缩短为一天。
- 手动指定日期和顺序可以超出预算，会显示警告；勾选景点、改变节奏或点击“重新规划”会重新自动安排。住宿区域按当前已安排景点重算。
- 安静偏好仅依据区域资料中的“清幽/安静”等描述；未收录相关资料时明确提示，不能保证实际噪声或房价。
- “一天一夜”按当天游览、住宿一晚、次日返程解释；其他时长按末日返程解释。
- 天气按所选旅行日期查询；超出近期预报范围时显示提示，继续生成其他模块。穿搭与物品依据行程逐日最低/最高温和雨雪数据，天气不可用时不给出具体温度建议。
- 地理编码失败会阻止生成；天气、住宿枢纽或地图失败会分别降级；推荐景点查询失败时提示重试。普通请求 12 秒超时，Overpass 请求 15 秒超时。
- 相同地理编码/景点查询缓存 24 小时、天气缓存 10 分钟、驾车路线缓存 1 小时，均仅保存在当前页面内存。重置或编辑输入会取消请求，旧结果不会覆盖新的选择。本机攻略列表另外使用浏览器 localStorage，可删除单份攻略或导出文件备份。
- 生成后自动加载本地地图库与在线底图，主攻略不等待底图。已移除要求 API Key 的 CARTO；使用 OpenStreetMap 标准地址，本地 file:// 页面按官方文档发送应用标识。加载状态等待实际瓦片结果，失败保留路线示意，支持手动重试。
- 自驾、打车、大巴使用驾车路线参考；大巴路线不代表真实班次。飞机、火车、高铁、邮轮仅显示直线示意。OSRM 查询失败同样退化为直线，页面图例会说明。
- 打印视图包含攻略文本及展开的景点详情，省略交互地图。天气与交通测试采用模拟数据，不能替代第三方在线服务可用性验证。

## 📝 操作与存档

1. 填写目的地，查看推荐景点。已收录目的地立即显示；其他地点点击“查看推荐景点”，同名地点需先确认候选。
2. 勾选想去的景点，设置起点、日期、方式与偏好，点击“按所选景点生成路线”。路线逐站展示游览建议和相邻景点交通；交通分钟数按距离与方式估算，实际线路可通过高德地图链接核实。
3. 展开“调整景点与每日顺序”，勾选需要游览的景点，或指定日期、调整先后顺序。地图与住宿区域随行程重算。
4. 点击“保存到本机”后，可从“本机攻略”列表恢复；恢复显示原有天气和数据时间，不会自动刷新天气；地图会重新加载。
5. 点击“导出 JSON”可保留手动行程；通过“导入攻略 JSON”恢复，单文件上限 1 MB。文件版本、枚举、坐标和景点引用均经过校验。
6. “复制输入链接”只分享输入偏好；在可访问的网站地址打开才适合远程分享。`file://` 页面请导出 JSON。接收者打开链接后需要主动生成。
7. 地图随攻略自动加载，默认聚焦目的地景点，可切换某一天或含出发地的完整旅程。“加载地图”可手动重试。地图组件随项目本地提供，底图仍需联网；底图失败时保留路线/标记并提示切换或使用交通链接。打印/PDF 包含攻略内容与景点详情，省略交互地图及编辑控件。

## 🧪 开发验证

规则测试仅需 Node.js 18 或更新版本：

```bash
node scripts/check.cjs
node --test tests/core.test.cjs tests/catalog.test.cjs tests/features.test.cjs tests/arrival.test.cjs
```

浏览器测试使用 Playwright，Windows 默认使用本机 Edge，其他系统默认使用 Playwright Chromium：

```bash
npm install
npm run check
npm test
# 非 Windows 环境先运行：npx playwright install chromium
npm run test:browser
```

测试脚本自行启动并关闭本地静态服务器，模拟天气、地理编码、路线及景点接口。Leaflet 脚本和样式默认从 CDN 获取；离线验证可通过 `QA_LEAFLET_JS`、`QA_LEAFLET_CSS` 指定缓存文件。可选 `PLAYWRIGHT_BROWSER_PATH` 指定浏览器，`QA_SCREENSHOT_DIR` 指定截图输出目录。
